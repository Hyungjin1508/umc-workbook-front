# 백엔드 Codex 후속 점검 프롬프트

2026-11-17에 전달받은 week8 실제 명세로 프론트를 수정했습니다.
이 문서는 백엔드 확인서에 남아 있는 점검 항목을 전달하는 용도입니다.
첨부할 문서는 `remaining-api-contract.md`입니다.

---

React 프론트는 전달해 준 백엔드 week8 명세를 기준으로 연동 코드를 맞췄습니다.
즐겨찾기 등록·목록은 favoriteId/movieId/createdAt, 단건 여부는 isFavorite를 읽습니다.
중복 즐겨찾기 409와 미등록 즐겨찾기 삭제 404를 처리하고 관련 캐시를 갱신합니다.
평점 목록은 원시 배열로 읽고, PATCH에는 score와 현재 comment를 함께 보냅니다.
JWT sub로 회원 ID를 읽으며, 프론트 별점 입력은 1~5 정수로 제한합니다.

지난 백엔드 확인서에 보고된 다음 세 항목을 점검하고 필요한 수정을 진행해 주세요.

1. 평점 PATCH 응답의 updatedAt

   RatingService.update가 flush 전에 DTO를 만들면 응답에 수정 전 시간이 담길 수 있다고 보고되었습니다.
   먼저 테스트로 재현한 뒤, 수정된 시각이 응답과 DB 조회에 일치하도록 처리해 주세요.
   score/comment와 응답 객체의 필드 구조는 기존 워크북 계약을 따릅니다.

2. 별점의 입력 타입 검증

   현재 Jackson이 4.9를 4로, 문자열 "4"를 숫자 4로 변환한다고 보고되었습니다.
   POST/PATCH 평점 요청에서 JSON 정수 1~5를 허용하도록 검증을 보완해 주세요.
   소수, 숫자 문자열, null, 누락, 범위 밖 값의 거부를 테스트하고 기존 정상 요청도 확인해 주세요.
   다른 API에 영향을 주는 전역 변환 설정을 고려한다면 영향 범위를 먼저 확인해 주세요.

3. JSON 파싱·경로 값 오류 응답

   잘못된 JSON에서 공통 code/message 없이 기본 오류 응답이 반환된다고 보고되었습니다.
   관련 예외를 검토하고 400 공통 JSON 응답으로 안내할 수 있도록 정리해 주세요.
   프론트에는 기본 오류 메시지 처리도 준비되어 있습니다.

추가 검증은 정상 즐겨찾기·평점 등록/수정/삭제, 중복 등록, 타인 평점 변경 차단을 포함해 주세요.
이전 확인서는 이 부분을 코드 검사로만 확인했다고 명시했습니다.
통합 테스트용 데이터나 별도로 식별되는 테스트 계정을 사용하고 생성한 테스트 데이터의 정리 방법을 알려 주세요.

완료 후 수정 파일과 테스트 결과, 실제 서버에서 확인한 범위, 추가로 필요한 정보를 정리해 주세요.
비밀번호·토큰·DB 비밀값은 출력에서 가려 주세요.
